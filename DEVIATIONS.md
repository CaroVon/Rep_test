3. `steer_compare_v4.py` optgap convergence fix (task-doc remedy "increase
   iterations or check precision"): at alpha_abs=5e-3 the Newton hyperplane
   minimizer failed for `dua_ctx` (16-20 rows/run) and a few `dua_unemb`/
   `cau_ctx` rows - only 84-87% of rows had gap >= -0.01 vs the 95% audit
   bar. KL on a hyperplane is convex, so negative gaps were optimizer
   failures. (a) First attempt `iters=40 -> 120`: NO effect (identical
   rows) - the loop exits via the line-search `else: break`, not the
   iteration cap. (b) Actual fix: `hyperplane_min` gained a `lam_init`
   parameter and the optgap call initializes Newton at the METHOD'S
   ENDPOINT (`lam_init=lam_end`), which lies on the hyperplane by
   construction (c = beta.lambda_end), instead of the projection of
   lambda_0 (a high-KL start from which descent stalled in fp32 noise).
   Objective and constraint unchanged - only the starting point of the
   same convex optimization. Validation probe (gemma1b_s0, alpha 5e-3,
   5 contexts): 100% of rows gap >= -0.01 (was 86%), dua_ctx gaps now
   +5.2..+7.3 (were about -13). All 5 optgap runs rerun with this fix.
   Steering outputs are unaffected (optgap runs after steering; the 19
   WP-A1 regression runs remain bit-identical).
4. GPU contention incident (2026-10-10 ~03:28-04:20): an earlier TaskStop
